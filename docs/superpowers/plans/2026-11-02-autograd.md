# Reverse Autograd Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Enable genuine Scala training through reverse-mode differentiation of CPU Float32 expressions.

**Architecture:** An `autograd` module depends on CPU kernels. Immutable `Variable` values hold Tensor data and immutable parent/pullback edges; a backward invocation owns its temporary gradient map, preventing stale intermediate accumulation. Leaf gradients accumulate across backward invocations until `zeroGrad`. Rank-2 GEMM uses numscala. Thread-local `noGrad` prevents graph construction and restores state on exceptions.

**Tech Stack:** Scala 3.3.8 LTS, sbt 2.0.10, Java 25, MUnit, numscala 0.5.0.

**Spec:** `docs/superpowers/specs/2026-11-02-scala-torch-design.md` (approved). This implements the autograd portion of M2; modules, optimizers, state_dict and real model training remain separate required work.

## Global Constraints

- Scala 3.3.8 LTS, Java 25, sbt 2.x.
- Python-free runtime and ordinary tests.
- Public in-place tensor mutations remain unavailable.
- Only CPU Float32 gradients supported in this stage; no silent device conversion.
- A small training demo does not complete the full LLM/diffusion/NUI goal.

## Review Focus

- Repeated edges and shared graph branches must add gradients exactly once per edge.
- Broadcast backward must reduce to the original shape, including scalar and empty axes.
- Fresh backward calls must not reuse stale intermediate gradients.
- noGrad must restore state after nested calls and exceptions and remain thread-local.
- Deep graphs must not overflow the JVM call stack.
