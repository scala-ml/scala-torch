# CPU Conv2d implementation plan

Execute inline under the approved diffusion/NUI design (M5). This is a prerequisite, not completion of diffusion.

1. Add a Float32 CPU NCHW/OIHW cross-correlation reference with positive pairwise stride/dilation, symmetric nonnegative height/width padding and channel groups. Explicit configuration avoids string padding modes. Validate shapes and bounded Int indexing before allocation; allow empty batches, reject empty channels/spatial dimensions.
2. Provide input/weight pullbacks with Double accumulation. Expose Variable.conv2d and a derived nn.Conv2d module; bias uses existing differentiable broadcasting. Preserve saved immutable inputs and existing stale-leaf/noGrad behavior.
3. Test analytical orientation/padding/groups/stride/dilation, noncontiguous tensors, all-parameter finite differences, empty batches and invalid dimensions. Watch missing APIs fail before implementation.
4. Run affected suites and full public/CUDA regression, request read-only review, document and commit.
5. Follow with CUDA convolution, normalization/upsampling, CLIP/U-Net/VAE/schedulers and actual NUI feature migration. Existing NUI inventory remains open.

Ruling: implement a direct reference kernel instead of im2col/GEMM initially to avoid expanded activation storage and establish a transparent numerical oracle. Performance implementation remains required separately.
