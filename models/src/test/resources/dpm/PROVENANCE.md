# DPM++ reference trajectory

## Full tiny-image reference

`image_reference.py` adds transformers 4.49.0 to the environment below and loads
the local `hf-internal-testing/tiny-sd-pipe` checkpoint at revision
`39f7e1819d772fbb8dd7f2aa3da8e2fc5a9bd917`. It uses eager CLIP/attention,
Float32 CPU inference, prompt `a red cat`, negative `a blue boat`, CFG 3,
three DPM++ 2M/Karras steps, and explicit 1x4x3x5 noise `(i % 7 - 3) * 0.125`.
No random seed equivalence between frameworks is assumed.

`image-f32.bin` contains the raw NCHW 1x3x6x10 VAE output (180 little-endian
Float32 values; no clipping or PNG quantization). SHA256:
`4dbb24c34998d8f1bce8a241cc875573f039485a819cec5eff1f527b1c4c4db4`.
The Windows Scala image pipeline matched with maximum absolute error
`3.7252903e-6`; its test threshold is `1e-4`. This one tiny-image case does not
prove SD1.5/SDXL quality, GPU parity, all prompts, or full NUI compatibility.

```
python image_reference.py <local-tiny-sd-root> image-f32.bin
```

## Solver-only trajectories

`uniform-trajectory.tsv` uses the same settings below with `use_karras_sigmas=False`
and default `timestep_spacing=linspace`. Regenerate with
`python reference.py uniform-trajectory.tsv uniform`. SHA256:
`a300fb807445688e1810b02195968d92f933019cb09f0a8497783098038f7cfe`.
It adds twelve reference updates across the same three prediction modes.

Generated by `reference.py` using CPython 3.12.12, torch 2.7.1+cpu,
diffusers 0.33.1 and numpy 2.5.4 on Windows. The scheduler version matches
NUI's pinned requirements. No model weights or random-number generation are
involved: inputs and per-step predictions are explicit two-element vectors.

Profile: DPMSolverMultistepScheduler, dpmsolver++, order two, midpoint,
Karras, terminal zero, 1000 scaled-linear betas 0.00085 to 0.012, four steps.
Three trajectories cover epsilon, sample and v_prediction. Each row records
the actual input, prediction and output as emitted by the upstream scheduler.

`trajectory.tsv` SHA256:
`ee9b33bc17640039c2d93e118ebf380103fb4ba0bc37809057037583f1a0a188`

Scala tests read the checked-in TSV without running Python. Solver comparisons
use upstream sigma values and feed each Scala output into its next update;
the separate schedule comparison permits 3e-5 absolute sigma error because
Scala accumulates training coefficients in Double and upstream uses Float32.
Model timesteps must match exactly. This does not establish full-image parity,
other step counts, other scheduler variants or NUI protocol compatibility.

Reproduction (in an isolated reference environment with the listed packages):

```
python reference.py trajectory.tsv
```

Upstream algorithm reference:
https://github.com/huggingface/diffusers/blob/v0.33.1/src/diffusers/schedulers/scheduling_dpmsolver_multistep.py
