# DPM++ reference trajectory

Generated by `reference.py` using CPython 3.12.12, torch 2.7.1+cpu,
diffusers 0.33.1 and numpy 2.5.4 on Windows. The scheduler version matches
NUI's pinned requirements. No model weights or random-number generation are
involved: inputs and per-step predictions are explicit two-element vectors.

Profile: DPMSolverMultistepScheduler, dpmsolver++, order two, midpoint,
Karras, terminal zero, 1000 scaled-linear betas 0.00085 to 0.012, four steps.
Three trajectories cover epsilon, sample and v_prediction. Each row records
the actual input, prediction and output as emitted by the upstream scheduler.

`trajectory.tsv` SHA256:
`ee9b33bc17640039c2d93e118ebf380103fb4ba0bc37809057037583f1a0a188`

Scala tests read the checked-in TSV without running Python. Solver comparisons
use upstream sigma values and feed each Scala output into its next update;
the separate schedule comparison permits 3e-5 absolute sigma error because
Scala accumulates training coefficients in Double and upstream uses Float32.
Model timesteps must match exactly. This does not establish full-image parity,
other step counts, other scheduler variants or NUI protocol compatibility.

Reproduction (in an isolated reference environment with the listed packages):

```
python reference.py trajectory.tsv
```
